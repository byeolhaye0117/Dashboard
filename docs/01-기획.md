# 헬스장 업무 대시보드 — 기획서 (v0.1)

> 이 문서는 확정본이 아니라 **합의를 쌓아가는 문서**입니다.
> `확정` 표시는 사용자가 답변한 내용, `제안` 표시는 제가 기본값으로 잡은 내용입니다.
> `제안` 항목은 언제든 뒤집을 수 있고, 뒤집으면 이 문서를 고칩니다.

---

## 1. 무엇을 만드는가

4~10개 지점을 운영하는 헬스장의 **회원·매출·상담·PT를 한 곳에서 입력하고 보는 웹 대시보드**.

기존 회원관리 프로그램이 없고 종이 장부로 운영 중이므로, 이 대시보드는
"보는 도구"가 아니라 **"입력 + 보는 도구"** 입니다. 사실상 소형 회원관리 시스템입니다.
이게 이번 프로젝트의 난이도를 결정하는 가장 중요한 사실입니다.

### 확정된 전제

| 항목 | 결정 | 근거 |
|---|---|---|
| 사용 주체 | 여러 지점 통합 관리 | 확정 |
| 지점 수 | 4~10개 | 확정 |
| 현재 데이터 | 없음 (종이 장부) | 확정 |
| 입력 방식 | 대시보드에서 직접 입력 | 확정 |
| 사용 기기 | PC 입력 + 휴대폰 조회 | 확정 |
| 운영 비용 | 무료 | 확정 |
| 기술 수준 | 가이드 따라 설치·배포 가능 | 확정 |
| 핵심 지표 | 매출/결제, 만료·재등록, 신규·상담전환, PT 세션 | 확정 |

## 2. 데이터 저장 — 어디에, 어떻게

### 2-1. 결론: Supabase (무료) + Cloudflare Pages (무료)

```
[관장·직원 브라우저]
        │  PC 입력 / 휴대폰 조회
        ▼
[React 웹앱]  ← Cloudflare Pages 에서 무료 호스팅
        │  HTTPS
        ▼
[Supabase]  ← PostgreSQL + 로그인 + 권한(RLS) 이 한 세트로 제공
```

### 2-2. 왜 이 조합인가

**Supabase를 고른 이유**
- PostgreSQL 정식 DB라 "만료 30일 이내 회원", "지점별 월매출" 같은 질문을
  나중에 얼마든지 새로 물어볼 수 있습니다. 엑셀/시트는 이게 갈수록 무너집니다.
- 로그인·비밀번호·권한이 DB에 내장(RLS)되어 있어서, **"A지점 직원은 A지점 회원만
  보인다"를 DB 레벨에서 강제**할 수 있습니다. 다지점 운영에서 이건 타협 대상이 아닙니다.
- 자동 백업, 웹 관리화면 제공. 직원이 실수로 지워도 복구 경로가 있습니다.

**Cloudflare Pages를 고른 이유 (Vercel이 아니라)**
- Vercel 무료(Hobby) 플랜은 약관상 **비상업적 용도 전용**입니다. 헬스장 사업 운영에
  쓰는 건 약관 위반 소지가 있어, 나중에 계정이 막히면 대시보드가 통째로 멈춥니다.
- Cloudflare Pages 무료 플랜은 **상업적 이용을 허용**합니다. 지금 이걸 골라두면
  나중에 갈아엎을 일이 없습니다.

### 2-3. 무료로 정말 되는가 — 한도 점검

10개 지점 × 지점당 500명 = 회원 5,000명 규모로 계산했습니다.

| 항목 | 무료 한도 | 예상 사용량 | 여유 |
|---|---|---|---|
| DB 용량 | 500MB | 5년치 약 50~80MB | 충분 |
| 로그인 사용자 | 월 5만 명 | 직원 20~30명 | 충분 |
| 사이트 트래픽 | 무제한 | — | 충분 |
| 배포 횟수 | 월 500회 | 수정할 때만 | 충분 |

**단, 무료 플랜의 실제 주의사항 2가지 (반드시 알고 가야 합니다)**

1. **7일간 아무도 접속 안 하면 Supabase 프로젝트가 일시정지**됩니다.
   매일 쓰는 대시보드라면 걸릴 일이 없지만, 명절 연휴에 전 지점이 쉬면 걸릴 수 있습니다.
   → 일시정지돼도 데이터는 안 지워지고 버튼 한 번으로 복구됩니다. 알고만 계시면 됩니다.
2. **무료 플랜은 자동 백업 보관 기간이 짧습니다.**
   → 월 1회 "전체 데이터 내려받기" 버튼을 대시보드에 넣어드릴 예정입니다.
   관장님 컴퓨터에 엑셀로 한 부 떨어뜨려 두면 최악의 상황에도 장부가 남습니다.

> 나중에 지점이 20개를 넘거나 백업을 더 촘촘히 하고 싶어지면
> Supabase 유료(월 3.5만원 수준)로 **코드 수정 없이** 올릴 수 있습니다.
> 지금 무료로 시작하는 게 나중을 막지 않습니다.

### 2-4. 개인정보에 대해

회원 이름·연락처를 다루므로, 처음부터 다음을 지킵니다.

- **최소 수집**: 주민번호·주소는 받지 않습니다. 이름/연락처/성별/생년 정도.
- **지점 격리**: DB 권한(RLS)으로 타 지점 회원 정보 접근을 원천 차단.
- **퇴사자 처리**: 직원 계정 비활성화 기능을 설정 화면에 둡니다.
- **회원 삭제 요청**: 회원이 요청하면 개인정보만 지우고 매출 통계는 남기는
  방식(익명화)으로 처리합니다.

## 3. 데이터 구조 (무엇을 저장하는가)

실제 헬스장 업무 흐름을 그대로 따릅니다.

```
지점(branches)
 └ 직원(staff)          … 관장 / 매니저 / 트레이너
 └ 상품(products)        … 3개월 회원권, PT 10회, 락커 3개월 …
 └ 상담(consultations)   … 문의 → 상담 → 등록/보류/이탈
      └ 회원(members)     … 상담이 등록으로 전환되면 회원이 됨
           └ 계약(contracts) … "이 회원이 이 상품을 언제~언제 샀다"
                └ 결제(payments)     … 실제 입금 (분할결제 대응)
                └ PT세션(pt_sessions) … 1회 진행 = 1건 기록
```

### 각 테이블이 답하는 질문

| 테이블 | 담는 것 | 이게 있어야 답할 수 있는 질문 |
|---|---|---|
| `branches` | 지점명, 오픈일, 주소 | 지점별 비교 전부 |
| `staff` | 이름, 역할, 소속지점, 재직여부 | 트레이너별 실적, 담당자별 등록 실적 |
| `members` | 이름, 연락처, 성별, 생년, 유입경로, 최초등록일 | 신규 회원 수, 유입경로별 성과 |
| `products` | 종류(기간권/PT/부가), 기간 or 횟수, 정가 | 어떤 상품이 잘 팔리나 |
| `contracts` | 회원, 상품, 시작일, **종료일**, 총세션, **잔여세션**, 담당자 | **만료 예정 회원**, 재등록률, 잔여 세션 |
| `payments` | 계약, 금액, 결제일, 결제수단 | **월 매출**, 지점별 매출, 미수금 |
| `pt_sessions` | 계약, 트레이너, 일시, 상태(진행/노쇼/취소) | 트레이너별 세션 수, 소진 속도 |
| `consultations` | 이름, 연락처, 상담일, 유입경로, 결과 | **상담 전환율**, 보류 고객 재문의 |

**설계상 중요한 두 가지**

- **계약과 결제를 분리**한 이유: 헬스장은 "3개월 등록하고 절반은 카드, 절반은
  다음 달에" 같은 일이 흔합니다. 하나로 합치면 매출 집계가 반드시 틀어집니다.
- **PT 세션을 1건씩 기록**하는 이유: "잔여 횟수" 숫자만 깎으면, 나중에
  "이번 달에 누가 몇 회 뛰었나", "노쇼가 많은 회원은 누구인가"를 영영 알 수 없습니다.
  체크 한 번에 1행이 쌓이면 두 질문 모두 답이 나옵니다.

핵심 설계 의도:
- **숫자만 보여주지 않고 "그래서 뭘 해야 하는지"를 같이 띄웁니다.**
  대시보드가 버려지는 가장 흔한 이유가 "예쁜데 볼 이유가 없어서"입니다.
- 상단 `전체 ▾` 를 지점으로 바꾸면 같은 화면이 그 지점 것으로 바뀝니다.

### 4-2. 나머지 화면

| 화면 | 하는 일 | 주 사용자 |
|---|---|---|
| **회원 관리** | 검색, 회원 상세(계약 이력·결제 이력·PT 이력 한 눈에) | 데스크 |
| **등록/결제 입력** | 회원 등록 + 상품 선택 + 결제 입력을 **한 화면에서** | 데스크 |
| **만료 관리** | 만료 임박 순 정렬, 연락 여부 체크, 재등록 처리 | 데스크 |
| **PT 세션** | 트레이너가 오늘 수업 체크(탭 한 번), 잔여 횟수 자동 차감 | 트레이너 |
| **상담 관리** | 문의 접수 → 상담 → 결과 기록, 보류 고객 재연락 알림 | 데스크 |
| **지점 비교** | 지점별 매출·신규·재등록률 순위표 | 관장 |
| **설정** | 지점·상품·직원 계정 관리, 데이터 내보내기 | 관장 |

### 4-3. 디자인 방향 (제안)

- **정보 밀도 우선.** 헬스장 데스크는 바쁩니다. 여백 예쁜 화면보다
  한 화면에 필요한 게 다 보이는 게 낫습니다.
- **색은 의미로만 사용.** 기본은 무채색, 색은 "만료 임박(주황)",
  "미수금(빨강)", "목표 달성(초록)" 같은 **경고·강조에만** 씁니다.
  전부 알록달록하면 아무것도 눈에 안 들어옵니다.
- **PC는 정보 밀도, 모바일은 카드 3장.** 관장님이 폰으로 볼 땐
  이달 매출·만료 임박·신규 등록 딱 3개만 크게 보이면 됩니다.
- **다크모드 지원.** 헬스장 조명이 어두운 곳이 많습니다.

## 5. 운영 방법 (도구보다 이게 더 중요합니다)

대시보드가 실패하는 이유의 90%는 기술이 아니라 **"입력이 끊겨서"** 입니다.
그래서 입력 부담을 아래처럼 설계합니다.

### 5-1. 누가 언제 입력하는가

| 시점 | 누가 | 무엇을 | 걸리는 시간 |
|---|---|---|---|
| 상담 발생 즉시 | 데스크 | 상담 1건 (이름·연락처·유입경로) | 20초 |
| 등록 발생 즉시 | 데스크 | 회원 + 상품 + 결제 | 60초 |
| 수업 종료 후 | 트레이너 | 세션 체크 (탭 1회) | 3초 |
| 매일 마감 | 데스크 | 없음 — 이미 다 들어가 있음 | 0분 |

**"나중에 몰아서 입력"을 구조적으로 막습니다.** 몰아서 입력하면 반드시
빠지고, 한 번 빠지면 숫자를 못 믿게 되고, 못 믿으면 아무도 안 봅니다.

### 5-2. 정기 운영 루틴 (제안)

- **매일 아침 (데스크, 3분)** — 홈의 "오늘의 할 일" 확인.
  7일 내 만료 회원에게 연락하고 체크박스 처리.
- **매주 월요일 (관장, 10분)** — 지점 비교 화면.
  전주 대비 신규·재등록률이 꺾인 지점 확인.
- **매월 1일 (관장, 20분)** — 전월 마감 확인 + 데이터 내보내기(백업).
  지점별 목표 대비 실적 리뷰.

### 5-3. 실수 대비

- 잘못 입력한 결제는 **삭제가 아니라 취소 처리** → 기록은 남고 매출에서만 빠집니다.
- 회원 이름 중복(동명이인)은 **연락처 뒷 4자리로 구분**해서 목록에 표시합니다.
- 모든 수정에 "누가 언제 고쳤는지" 기록이 남습니다.

## 6. 만드는 순서 (제안)

한 번에 다 만들면 완성 전까지 아무것도 못 씁니다. 3단계로 쪼갭니다.

### 1단계 — "장부를 옮긴다" (핵심)
지점 / 직원 계정 / 상품 등록 → 회원 등록 → 계약·결제 입력 →
만료 예정 목록 → 매출 요약 → 홈 대시보드

이 단계만 끝나도 **종이 장부를 버릴 수 있습니다.** 여기가 최우선입니다.

### 2단계 — "영업을 붙인다"
상담 관리 + 전환율 · PT 세션 체크 + 트레이너별 실적 · 지점 비교 화면

### 3단계 — "편해진다"
데이터 내보내기(백업) · 만료 임박 알림 · 모바일 화면 다듬기 · 유입경로별 성과 분석

> 각 단계가 끝날 때마다 실제로 써보고, 안 쓰는 화면은 다음 단계에서 뺍니다.
