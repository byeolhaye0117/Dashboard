# 설치와 실행

두 단계입니다.

1. **지금 바로 화면 보기** — 설치할 게 거의 없습니다 (5분)
2. **실제로 쓰기** — Supabase 연결 (30분)

---

## 1. 지금 바로 화면 보기

Supabase 없이도 데모 데이터로 전체 화면이 돌아갑니다.
쓸지 말지 판단하려면 이것부터 해보세요.

### 준비물

[Node.js](https://nodejs.org) 20 이상. 사이트에서 LTS 버전을 받아 설치하면 됩니다.

### 실행

터미널(명령 프롬프트)을 열고:

```bash
cd web
npm install
npm run dev
```

브라우저에서 **http://localhost:5173** 을 엽니다.

지점 5개, 회원 약 640명, 상담 1,900여 건의 가짜 데이터가 들어 있습니다.
화면 왼쪽 위에 `데모 데이터` 표시가 붙어 있으면 데모로 돌고 있는 것입니다.

여기서 마음껏 눌러보세요. 등록도 해보고 지점도 바꿔보세요.
**새로고침하면 원래대로 돌아갑니다.** 망가뜨릴 수 없습니다.

## 2. 실제로 쓰기 — Supabase 연결

### 2-1. Supabase 프로젝트 만들기

1. [supabase.com](https://supabase.com) 가입 (무료, 카드 등록 없음)
2. **New project** 클릭
3. 입력할 것
   - **Name**: `gym-dashboard` (아무거나)
   - **Database Password**: 아무거나 만들고 **어딘가에 적어두세요**
   - **Region**: `Northeast Asia (Seoul)` — 한국에서 쓰니 서울로
4. **Create new project** → 2분쯤 기다립니다

### 2-2. 표 만들기

프로젝트가 준비되면 왼쪽 메뉴에서 **SQL Editor** 를 엽니다.

아래 파일을 **순서대로** 하나씩 열어서, 내용을 통째로 복사해
SQL Editor에 붙여넣고 **Run** 을 누릅니다.

| 순서 | 파일 | 하는 일 |
|---|---|---|
| 1 | `supabase/migrations/0001_init.sql` | 표 13개, 조회식, 지점 권한 |
| 2 | `supabase/migrations/0002_register_member.sql` | 회원 등록 처리 |
| 3 | `supabase/migrations/0003_product_unique.sql` | 상품 중복 방지 |
| 4 | `supabase/seed.sql` | 지점·상품·유입경로 초기값 |

> **4번은 실행 전에 내용을 고치세요.** 지점 이름과 상품·가격이 예시로
> 들어 있습니다. 실제 지점과 상품으로 바꿔서 실행하면 됩니다.
> 나중에 화면에서도 고칠 수 있지만, 지금 넣어두면 편합니다.

각 단계에서 `Success. No rows returned` 가 뜨면 정상입니다.

### 2-3. 직원 계정 만들기

**Authentication → Users → Add user → Create new user**

관장님 계정부터 만듭니다. 이메일과 비밀번호를 넣고 만들면
목록에 뜨는데, 그 줄의 **UUID를 복사**합니다.

다시 **SQL Editor** 로 가서 아래를 실행합니다.
(`여기에-붙여넣기` 자리에 방금 복사한 UUID를 넣으세요)

```sql
insert into public.staff (id, branch_id, name, role) values
  ('여기에-붙여넣기', null, '관장님 이름', 'owner');
```

`branch_id` 가 `null` 이면 **전 지점**을 볼 수 있습니다.

지점 직원은 이렇게 추가합니다.

```sql
insert into public.staff (id, branch_id, name, role) values
  ('직원-계정-UUID',
   (select id from public.branches where code = 'GN'),   -- 지점 코드
   '김데스크', 'desk');
```

역할은 4가지입니다.

| 역할 | 볼 수 있는 범위 | 할 수 있는 일 |
|---|---|---|
| `owner` | 전 지점 | 전부 |
| `manager` | 자기 지점 | 회원·결제 입력, 상품 관리 |
| `desk` | 자기 지점 | 회원·결제·상담 입력 |
| `trainer` | 자기 지점 | PT 세션 체크만 (결제는 못 건드림) |

### 2-4. 앱에 연결

Supabase 왼쪽 메뉴 **Project Settings → API** 에서 두 값을 복사합니다.

- **Project URL**
- **anon public** 키

터미널에서:

```bash
cd web
cp .env.example .env
```

만들어진 `.env` 파일을 메모장으로 열어 채웁니다.

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGci...
```

> **anon 키는 공개돼도 되는 값입니다.** 브라우저에 그대로 실립니다.
> 실제 차단은 DB의 권한 규칙(RLS)이 합니다.
>
> **`service_role` 키는 절대 넣지 마세요.** 그 키는 모든 권한 검사를
> 우회하므로, 브라우저에 실리면 전 지점 데이터가 통째로 열립니다.

다시 실행합니다.

```bash
npm run dev
```

`데모 데이터` 표시가 사라졌으면 실제 DB에 붙은 것입니다.

## 3. 인터넷에 올리기 (직원들이 쓸 수 있게)

### Cloudflare Pages — 무료, 상업적 이용 가능

> 흔히 쓰는 Vercel의 무료 플랜은 **약관상 비상업적 용도 전용**입니다.
> 헬스장 운영에 쓰다가 계정이 막히면 대시보드가 통째로 멈춥니다.
> Cloudflare 무료 플랜은 상업적 이용을 허용하므로 이쪽을 씁니다.

1. 이 저장소를 GitHub에 올립니다
2. [dash.cloudflare.com](https://dash.cloudflare.com) 가입
3. **Workers & Pages → Create → Pages → Connect to Git**
4. 저장소를 고르고 아래처럼 설정합니다

   | 항목 | 값 |
   |---|---|
   | Framework preset | `None` |
   | Build command | `npm install && npm run build` |
   | Build output directory | `web/dist` |
   | Root directory | `web` |

5. **Environment variables** 에 `.env` 에 넣었던 두 값을 똑같이 추가
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
6. **Save and Deploy**

몇 분 뒤 `xxx.pages.dev` 주소가 나옵니다. 직원들에게 이 주소를 알려주면 됩니다.

### 새로고침하면 404가 뜰 때

여러 화면이 있는 앱이라 서버에 알려줘야 합니다.
`web/public/_redirects` 파일이 이미 들어 있으니 그대로 두면 됩니다.

## 4. 백업 (월 1회, 3분)

무료 플랜은 자동 백업 보관 기간이 짧습니다.
**매월 1일에 한 번** 아래를 해두면 최악의 경우에도 장부가 남습니다.

Supabase → **SQL Editor** 에서 실행하고, 결과 오른쪽 위
**Download CSV** 를 누릅니다.

```sql
select m.name as 이름, m.phone as 연락처, b.name as 지점,
       p.name as 상품, c.started_on as 시작일, c.ends_on as 만료일,
       c.contract_price as 계약금액,
       coalesce(sum(pay.amount), 0) as 결제합계
  from public.contracts c
  join public.members m  on m.id = c.member_id
  join public.branches b on b.id = c.branch_id
  join public.products p on p.id = c.product_id
  left join public.payments pay on pay.contract_id = c.id
 group by m.name, m.phone, b.name, p.name, c.started_on, c.ends_on, c.contract_price
 order by c.started_on desc;
```

> Supabase 무료 플랜은 **7일간 아무도 접속하지 않으면 프로젝트가 일시정지**
> 됩니다. 데이터는 지워지지 않고 버튼 한 번으로 되살아납니다.
> 매일 쓰는 대시보드라면 걸릴 일이 없지만, 긴 연휴에는 한 번 열어보세요.

## 5. 개발자용

### 스키마·계산 로직 검증

Supabase 계정 없이 로컬 PostgreSQL로 전부 확인할 수 있습니다.

```bash
./supabase/run-tests.sh
```

정지에 따른 만료일 재계산, 분할결제 월별 분리, 환불 차감,
PT 세션 집계, 상담 전환, 지점 격리 등 22개 항목을 검증합니다.

### 화면 동작 검증

```bash
cd web
npm run dev            # 다른 터미널에서 띄워둔 채로
node interaction-test.mjs
```

등록 폼 계산, 저장, 상담 전환, 정렬, 지점 필터를 실제로 클릭해서 확인합니다.

### 화면 캡처

```bash
node shot.mjs
```

주요 화면을 라이트/다크/모바일로 캡처하고, 가로 스크롤이
생기는 곳이 있는지 검사합니다.
